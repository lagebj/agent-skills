# Branch and worktree safety

## Determine the base

Prefer repository evidence:

```bash
git symbolic-ref --quiet --short refs/remotes/origin/HEAD
git remote show origin
gh repo view --json defaultBranchRef
```

Fetch before branching when network and credentials permit. Do not merge or rebase remote changes blindly into a dirty worktree.

## Existing changes

Classify each path as:

- intended for this task;
- unrelated user work;
- generated by the task;
- local configuration or secret;
- obsolete and intentionally deleted;
- unknown.

Unknown changes are not safe to commit or delete.

## Safe isolation

Preferred order:

1. Create the task branch before editing.
2. If edits already exist on the default branch, create a branch at the current HEAD and keep the worktree.
3. Use a separate worktree for truly independent work when repository state permits.
4. Stash only when explicitly appropriate, label it clearly, and restore it before completion.

## Destructive operations

Treat these as high risk:

```text
git reset --hard
git clean -fd
git checkout -- <path>
git restore --source=<ref> -- <path>
git push --force
```

Do not use them to erase ambiguity. Establish ownership and evidence first.
